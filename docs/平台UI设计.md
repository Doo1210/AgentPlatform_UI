# 平台 UI 设计

更新日期：2026-11-02

本文整理平台导航栏与右侧内容区的 UI 场景及排版需求，分为两个主章节：

- **导航栏**：按品牌区、业务导航区、平台工具区、账户区划分，分别说明通用需求及展开、收起时的差异。
- **右侧内容区**：按“顶部结构＋内容结构”组合设计，共包含 5 种顶部结构和 4 种内容结构。

本文作为 UI 设计与实现依据，不表示文中所有场景及业务功能均已实现。

## 一、导航栏

### 1.1 整体布局与交互

- 导航栏位于页面左侧，占满可用窗口高度。
- 从上到下排列：**品牌区 → 业务导航区 → 平台工具区 → 账户区**。
- 品牌区固定在顶部，平台工具区和账户区固定在底部。
- 业务导航区占据中间剩余空间，超出时独立滚动。
- 展开宽度为 **180px**，收起宽度为 **60px**。
- 只由用户手动展开、收起，并记住选择；切换菜单不自动改变导航宽度。
- 展开、收起时使用平滑过渡，右侧内容同步调整宽度。

### 1.2 品牌区

用于展示平台身份，提供导航展开、收起入口。

#### 通用需求

- Logo 清晰，保持比例，不拉伸。
- 展开、收起入口始终可找到，位置稳定，视觉轻量。
- 点击 Logo 返回平台总览。

#### 展开态

- 展示完整 Logo，包含平台名称或品牌文字。

#### 收起态

- 展示简化 Logo 或品牌标志。
- 隐藏无法在窄栏中完整展示的品牌文字，避免裁切、换行。

### 1.3 业务导航区

用于进入各业务模块。

#### 通用需求

- 菜单按业务关系分组，顺序保持稳定。
- 分组标题是静态说明，不承担点击或展开、收起操作。
- 菜单项支持普通、悬停、选中及键盘聚焦状态。
- 当前页面对应的入口持续高亮。
- 业务模块内部功能通过右侧 Tab 或下拉框切换，不继续增加主导航子菜单。
- 内容超出可用高度时，仅业务导航区独立滚动，底部区域不被挤出。
- 滚动条保持细窄，避免占用过多空间。
- 根据当前组织的开通状态及用户权限显示入口，隐藏项不留空位。

#### 展开态

- 菜单项采用“图标＋名称”。
- 图标、文字起点及行高统一。
- 分组标题使用较小、较弱的文字，与菜单项拉开层级。

#### 收起态

- 只展示菜单图标，图标水平居中。
- 隐藏菜单名称、分组标题及文字徽标。
- 分组之间使用轻量短分隔线，保留原有顺序和分组关系。
- 悬停或键盘聚焦时，在导航右侧显示完整名称提示。
- 提示浮层不阻挡相邻入口，不影响连续切换。

#### 工业引擎专属导航

- 进入工业引擎后，仅替换业务导航区，展示该引擎的专属菜单。
- 品牌区、平台工具区和账户区保留。
- 提供明确的“返回主平台”入口。
- 专属菜单同样支持展开、收起，不另外并排增加导航栏。

### 1.4 平台工具区

用于放置 API Key、用量统计、平台运营、管理中心等公共入口。

#### 通用需求

- 固定在业务导航区下方、账户区上方。
- 与业务导航保持适当分隔，整体轻量、紧凑。
- 根据角色及权限显示入口，隐藏后重新排列。
- 图标风格、悬停及选中状态保持统一。
- 图标入口提供完整名称提示。
- 有子菜单的入口通过浮层展示，不撑开整条导航。

#### 展开态

- 工具图标横向紧凑排列。
- 保持与账户区一致的左右边距。

#### 收起态

- 工具图标改为纵向单列排列。
- 图标居中，点击范围与业务菜单图标协调。
- 子菜单从导航右侧弹出，并根据窗口空间调整位置。

### 1.5 账户区

用于展示当前身份，并提供组织与账户操作。

#### 通用需求

- 固定在导航栏最底部。
- 提供个人信息、组织切换、帮助、登出等入口。
- 用户菜单、组织切换浮层相互独立，打开一个时关闭另一个。
- 点击浮层外部或按 Esc 可以关闭。
- 浮层之间可一次点击切换，避免叠加遮挡。

#### 展开态

- 展示头像、用户名、角色和当前组织。
- 用户菜单与组织切换使用清晰、独立的入口。
- 较长的用户名或组织名称省略显示，并提供完整名称提示。

#### 收起态

- 导航栏内仅保留头像入口。
- 点击头像后，通过浮层展示用户身份、当前组织及相关操作。
- 组织切换仍可从浮层中完成，避免收起后丢失功能入口。

### 1.6 窄屏适配

- 导航栏通过菜单按钮以抽屉形式打开。
- 抽屉内优先展示完整文字导航。
- 选择菜单后关闭抽屉，展示对应内容。
- 支持点击遮罩、关闭按钮或按 Esc 关闭。
- 业务菜单独立滚动，品牌、平台工具和账户入口保持可访问。

## 二、右侧内容区

### 2.1 通用排版规范

#### 2.1.1 页面容器

- 除平台总览外，右侧内容统一使用白色圆角背景。
- 背景圆角为 **16px**。
- 内容内边距统一为 **20px 20px 16px**。
- 背景容器外保留页面边距。
- 不重复展示顶部模块标题，以及“技能／共 X 项”这类列表标题行。
- 需要展示页面名称和说明时，将其放入概览区。
- 平台总览保留独立排版；业务页面内部的概览区属于本文定义的 UI 场景。

#### 2.1.2 Tab 与工具栏

- 一级 Tab 使用文字、选中下划线和下方通栏分隔线，整体保持紧凑。
- 二级 Tab 与一级 Tab 使用不同样式，明确展示层级。
- 搜索框、下拉筛选等控件靠左排列。
- 有二级 Tab 时，搜索、筛选紧接在二级 Tab 后面，控件间距约 **8px**。
- 创建、新增等主操作靠右排列。
- 工具栏上间距约 **6px**，上下内边距约 **4px**，单行高度约 **40px**。
- 搜索框及下拉筛选框高度约 **28px**。
- 不给工具栏和整块数据列表增加外围线框。

#### 2.1.3 滚动规则

- 列表和卡片页只在数据区域上下滚动。
- 顶部一级 Tab、二级 Tab、条件筛选、搜索和操作栏保持固定。
- 表格滚动时，表头保持可见。
- 分页放在数据滚动区之外，保持固定。
- 避免整页与内部数据区同时出现纵向滚动条。
- 长说明、长表单按阅读和操作需要滚动，不机械套用数据列表的滚动规则。

#### 2.1.4 页面状态与窄屏适配

- 加载、空结果和异常提示显示在数据区内。
- 数据状态变化时，顶部条件与操作保持可用。
- 窄屏允许控件换行，避免重叠、截断或整页横向溢出。
- 换行时保持“Tab／搜索筛选在前，主操作在后”的顺序。
- 卡片随可用宽度减少列数。
- 表格列较多时，横向滚动限制在数据区域内。

### 2.2 顶部结构场景

#### 2.2.1 无 Tab

**结构：工具栏 → 数据区**

UI 需求：

- 页面直接从搜索、类型、状态等控件开始。
- 不预留 Tab、重复标题或 Tab 分隔线的位置。
- 搜索、筛选靠左，创建等主操作靠右。
- 数据紧接工具栏下方，减少纵向留白。
- 工具栏固定，数据区独立滚动。

适用组合：无 Tab＋列表、无 Tab＋卡片。

#### 2.2.2 单层 Tab

**结构：一级 Tab → 通栏分隔线 → 工具栏 → 数据区**

UI 需求：

- 一级 Tab 用于切换主要功能或资源类型。
- 选中项使用加粗文字和蓝色下划线。
- Tab 下方增加通栏横线，与下方内容分隔。
- 不同页面的 Tab 高度、间距及分隔线保持一致，减少顶部留白。
- 切换 Tab 后更新对应内容，并记住本次会话中的选择。
- 切换时重置不适用的搜索或筛选条件。
- 一级 Tab 和工具栏固定，数据区独立滚动。

适用组合：单层 Tab＋列表、单层 Tab＋卡片。

#### 2.2.3 双层 Tab

**结构：一级 Tab → 分隔线 → 二级 Tab＋工具栏 → 数据区**

UI 需求：

- 一级 Tab 切换主要功能或资源类型。
- 二级 Tab 切换当前功能内部的视图，或切换当前数据范围。
- 内部视图示例：评测任务／评测数据集。
- 范围筛选示例：全部／我的收藏／我的创建。
- 二级 Tab 使用浅灰蓝色圆角底座、白色选中块、蓝色加粗选中文字。
- 二级 Tab 字号为 **12px**，按钮高度约 **26px**，尺寸小于一级 Tab。
- 搜索、下拉筛选紧接二级 Tab，主操作靠右。
- 不需要二级选项时省略该区域，不留下空行。
- 一级、二级选择分别记住本次会话状态，避免切换后丢失当前位置。
- 两层 Tab 和工具栏固定，数据区独立滚动。

适用组合：双层 Tab＋列表、双层 Tab＋卡片、双层 Tab＋分栏。

#### 2.2.4 带条件筛选区

**结构：一级 Tab → 分隔线 → 筛选条件区 → 工具栏 → 数据区**

UI 需求：

- 筛选条件按行展示，每行由“条件名称：选项”组成。
- 不同条件行的名称和选项起点对齐，保持紧凑行距。
- 普通选项使用无边框文字，选中项使用蓝底白字。
- 筛选条件不使用二级 Tab 的分段底座样式。
- 每类条件提供“全部”，只重置当前类别的选择。
- 不同类别条件组合生效，并可与搜索、下拉筛选共同使用。
- 搜索框、下拉筛选和操作按钮独立放在筛选条件区下方，不混入条件行。
- 搜索、下拉筛选靠左，创建等主操作靠右。
- 切换一级 Tab 时，重置不适用的条件。
- 条件筛选区和工具栏固定，数据区独立滚动。

适用组合：多维条件筛选＋卡片、多维条件筛选＋列表。

#### 2.2.5 无 Tab＋概览区

**结构：概览区 → 工具栏 → 数据区**

UI 需求：

- 概览区包含页面名称、简短说明和关键指标。
- 标题、说明与指标紧凑排列，不以大面积宣传横幅替代业务概览。
- 指标可展示总数量、运行中数量、累计调用次数等整体情况。
- 概览默认展示模块整体指标，列表筛选只影响数据区，避免指标含义不清。
- 搜索、类型和状态筛选靠左，新增等主操作靠右。
- 概览和工具栏保持固定，仅下方数据区滚动。

适用组合：无 Tab＋概览＋列表、无 Tab＋概览＋卡片。

### 2.3 内容结构场景

#### 2.3.1 列表型

适用于需要逐项比较的数据。

UI 需求：

- 使用纵向数据行或表格，保持列和字段对齐。
- 通过轻量横向分隔线区分数据行，不增加整块列表的外围线框。
- 列表行高约 **58px**，兼顾信息密度和可读性。
- 名称、状态、时间等信息层级清楚。
- 行内操作与工具栏主操作区分，避免每行都使用醒目的主按钮。
- 表头固定，分页位于滚动区外，仅数据内容上下滚动。

#### 2.3.2 卡片型

适用于专家、工作流、资源库等对象展示。

UI 需求：

- 卡片展示图标、名称、简要说明、状态及必要信息。
- 卡片的圆角、间距和高度保持统一。
- 使用自适应网格，随宽度变化调整列数。
- 草稿使用灰色状态样式，已发布、可用等使用对应状态样式。
- 卡片布局保留搜索、筛选和创建等操作能力。
- 不再给整个卡片网格增加外围线框。
- 卡片区域独立滚动，顶部导航、条件和操作保持固定。

#### 2.3.3 分栏型

适用于对象选择、预览和配置需要同时显示的场景。

UI 需求：

- 左侧承担对象选择，右侧承担预览或配置；必要时可拆为多栏。
- 列宽根据内容分配，避免各栏机械等宽。
- 顶部 Tab、筛选和操作栏保持固定。
- 分栏内容位于数据区域内，避免整页与内容区同时滚动。
- 选中对象后，关联预览和配置内容同步更新。
- 窄屏根据阅读顺序将多栏调整为纵向排列，保持对象选择与详情的关联。

#### 2.3.4 纵向编排型

适用于说明、表单、图表与配置区块的组合。

UI 需求：

- 区块按阅读、填写或操作顺序排列。
- 各区块保持统一的对齐、层级和间距。
- 长说明、长表单允许按内容阅读滚动。
- 嵌入的数据列表或表格单独处理数据滚动。
- 保存、提交等操作位置保持稳定，避免用户寻找操作入口。

### 2.4 页面组合方式

具体页面需明确以下内容：

1. 采用哪一种顶部结构。
2. 搭配哪一种内容结构。
3. 哪些区域固定，哪些区域滚动。
4. 搜索、筛选和主操作分别放在哪里。
5. 是否需要表头、分页、概览或二级视图。

典型组合包括：

- 无 Tab＋数据列表。
- 单层 Tab＋卡片网格。
- 双层 Tab＋数据列表。
- 条件筛选区＋卡片网格。
- 单层 Tab＋分栏内容。
- 无 Tab＋概览区＋数据列表。
